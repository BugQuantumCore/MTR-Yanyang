# 晏阳 MTR 1.21.x 代码审查与优化说明

审查日期：2026 年 11 月 14 日。主项目基线为 `effe968c`，TSC 依赖基线为 `41187a10`。

成果位于主模组草稿 PR #2（`perf/1.21-render-simulation-audit`）及 TSC 草稿 PR #1（`fix/tsc-passenger-lifecycle-audit`）。主工作流固定使用已审查的 TSC 提交 `60a5e8c1be1691c384f24855093188a4e9cf23bd`，避免构建时依赖分支漂移。本次没有合并主分支或发布正式版本。

**严格遵守要求：没有在本地执行构建、测试、基准或启动游戏。** 本地仅获取、阅读、修改源码及检查 Git 差异；编译、回归执行、着色器验证和产物验证均交给 GitHub Actions。不能把 CI 编译成功等同于 Vulkan 驱动、Radiance 画面或多人游戏验证成功。

## 已落实的主要优化与修复

| 领域 | 实际修改 | 验证边界 |
|---|---|---|
| Rust/C++ Vulkan | 修正 64 位设备句柄、std140 偏移、设备 UBO 对齐、内存类型掩码、shader entry point、初始化死锁及部分失败清理；修正 OBJ 材质索引和组过滤；复用帧快照、相邻姿态矩阵和网格绑定 | 记录式 Vulkan 测试不等于真实显卡验证 |
| 原生模型提交 | 每次整模型放置只请求一次，再选择对应材质网格，消除逐材质重复放置整模型的二次复制；生产纹理复用宿主 GPU 图像、视图和采样器 | 尚未完成宿主 fence/frame-slot 所有权协议 |
| 通信与线程 | 协议升级 v3，保留 FRM2 帧布局；默认共享内存构建队列 + JDK 21 JNI 同步提交帧，FFM 使用正式 API；Java/Rust 对应 acquire/release，检查实际映射边界 | 不能将异步构建线程用于录制宿主活动命令缓冲 |
| Radiance/OpenGL | Radiance 通过可捕获的 RenderType/MeshData 通道批量提交模型；修复 OpenGL VBO 绑定和 shader colour 恢复 | 透明材质、光照、后端切换仍需游戏验证 |
| 列车碰撞 | 更新移动/插入碰撞快照，保留完整车号与车厢键，修复高帧率速度估算和包含关系推出距离；世界 AABB 计算复用矩阵与半尺寸；局部 Blockbench 边界计算八角点并包含膨胀 | 保留保守世界 AABB，未实现精确 OBB、连续碰撞或斜坡地板 |
| AI 乘客/TSC | 修复首节车厢选择、连接段、非法编组长度、删除车辆引用、同线路行程同步、步行换乘网格覆盖；路径队列拒绝立即回退，失败缓存可重试 | 同 ID 车辆替换的乘客迁移仍需明确策略 |
| 车辆资源 | 默认地板/门区写入实际返回缓存；空模型不崩溃；所有转向架就绪后再建门模型；编辑器往返保留载客量 | 共享 holder 在不同编组之间的门映射归属尚未重构 |
| 动态纹理/缓存 | 有界生成队列、每帧上传预算、工作线程裁切、过期结果隔离、字体回退缓存、会话资源清理；地图顶点缓冲在替换/淘汰/换世界时释放 | 大图片需要进一步按解码字节预算限制 |
| GPU 色板 | 两套颜色选择器由逐像素 CPU 生成四边形，改为 HSB 平面 2 个四边形和 hue 条 6 段，由 GPU 插值/混合完成 | 这只是工作量下降；sRGB、alpha、Vulkan 实际色彩需要验证 |
| 网络与输入 | 数据包发送有效字节、释放缓冲、按连接隔离组装并限制字节/数量/超时；校验余额购买和乘客 UUID；限制转发 URL authority；资源包和地图缓存路径约束、上传限额 | 未建立完整驾驶、远程编辑和本地 HTTP 授权模型 |
| 方块/声音/UI | 修复相对 tick 调度、16 向信号朝向、标牌数组长度、传感器 NBT、无效播报和队列生命周期、BVE 制动状态与小数充气量；修复信号缓存键冲突、PIDS 空语言取模、重复 checkbox 翻转 | 这些交互仍需游戏、多客户端和存档回读检查 |

没有宣称提高某个百分比的 FPS，也没有以本地跑分代替验证。AI 与碰撞计算继续在 CPU 执行，避免依赖无显卡服务器无法提供的 GPU，以及引入尚未设计的异步同步成本。新增乘客／列车碰撞仅作用于客户端玩家，不构成服务端权威碰撞或防作弊机制。

## 仍应优先处理的项目

1. 宿主 GPU fence/frame-slot 与 descriptor/UBO 生命周期；原生失败后 native-only 模型的 Java 重建、每顶点颜色与透明阶段画面。
2. 预览界面 RenderTarget 关闭释放和异常后的渲染状态恢复；资源包编辑器跨线程共享状态及 PNG 解码像素预算。
3. 共享模型的跨列车显示文字、跨编组门映射；Blockbench 实际嵌套加载的父变换链。新增八角点测试只验证直接提供的变换链与烘焙顶点，不能宣称整个嵌套加载流程已修复。
4. 大规模轨道建造的逐条全量广播、无界递归、粗粒度 tick 时间预算；轨道编辑器每帧大范围世界扫描、长列表可见区裁剪与地图 LOD。
5. 多人服务器权限、客户端驱动的信号/传感器行为及其他玩家的方块状态同步。
6. 发布工作流还需核对配置中的构建 run 是否成功、来自预期工作流及对应源码提交，并让 release tag 指向产物的源码提交。当前原生工作流的 JAR 哈希核对不等于发布流程已有完整来源保证；本轮没有创建或发布 release。

每项的具体源码位置、触发条件、优先级和没有修复的原因均写在上述专项报告中，避免在同一次修改中悄悄重设计共享资源或服务器权限。
