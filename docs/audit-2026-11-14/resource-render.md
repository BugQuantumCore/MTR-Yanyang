## Fixes completed in this batch

1. **Rotated/inflated Blockbench collision bounds.** `resource/BlockbenchElement.java:31-105` previously rotated only two opposite corners, omitting extrema and the group transforms actually applied by the renderer. The bounds now transform all eight inflated cube corners using the existing applied matrix chain, preserving the established collision-coordinate convention. This is load-time work, not per-frame work. Rendering geometry and outline traversal semantics are unchanged. `BlockbenchElementBoundsTest` contains five source cases comparing the returned bounds against actual baked `StoredVertexData`: an offset unrotated cube, a 45-degree square, noncentral origin and compound rotation, group transforms plus inflation/mirroring, and a zero-thickness rotated floor. The group fixture supplies its transform chain directly to the element; it is not an end-to-end test of nested outline loading, and does not validate or repair the pre-existing loader parent-chain issue below.
2. **Fallback collision geometry reached the wrong lists.** `resource/VehicleResource.java:393-418` now fills the floor/doorway lists actually retained by `VehicleResourceCache`, rather than mutating a model holder after aggregation. Empty model collections no longer call `getFirst()` and do not acquire invented fallback geometry. Door mapping now runs after bogie readiness succeeds, preventing repeated append/rebuild work during asynchronous bogie loading retries. `VehicleResourceDataTest` includes fallback/cached floor-area and empty-resource source cases.
3. **Capacity lost in resource-editor round trips.** `VehicleResource.toVehicleResourceWrapper` passes capacity into the hand-written wrapper constructor, which explicitly stores the optional schema field. A third `VehicleResourceDataTest` case checks capacity 137 through resource, wrapper, JSON, wrapper and resource.
4. **Signal cache aliases unrelated coordinates and worlds.** `render/RenderSignalBase.java:159-204` no longer uses overlapping int shifts masquerading as a long packing. The old expressions alias `(2048,0,0)` with `(0,0,1)` and `(1,0,0)` with `(0,256,0)` for the same facing. `SignalNodeCacheKey` uses world identity through a weak reference, an immutable full-coordinate `BlockPos`, and independent direction. It preserves the 500ms TTL and 1024-entry ceiling; periodic cleanup drops expired/dead-world entries, and `MTRClient` clears it at disconnect and world/dimension change. No cache key strongly retains a world. `SignalNodeCacheKeyTest` adds three source cases covering the known collisions, world-border coordinates, all facings, distinct value-equal worlds, and mutable input positions.
5. **PIDS separator-only input crashes rotation.** `render/RenderPIDS.java` now routes custom messages, destination, route number and station name through `PidsLanguageText`. Existing Java split semantics are retained for normal input; a zero-field result becomes one empty language so modulo/index operations remain defined. `PidsLanguageTextTest` has three source cases for separator-only, normal multilingual/trailing-separator, and empty text behavior.

This child added **14 test methods across four new test files**. The parent owns staging, commits, publication and GitHub CI. Repository edits are frozen after the signal/PIDS batch; further observations below are registered follow-ups, not silently expanded into this change set.

## Unresolved findings and follow-up priorities

1. **P2, confirmed ownership mismatch — model display text is cached without vehicle identity.** `resource/ModelPropertiesPart.java:38-39,399-455` has one `cachedText`/timeout on an object shared through cached vehicle model resources. Two vehicles using the same model can display the first vehicle's destination/route/station until the 1-1.5 second TTL expires. Correctness needs a bounded vehicle/state-keyed cache or vehicle-owned text state; simply increasing/decreasing the timeout does not fix ownership. No runtime reproduction was performed.
2. **P2, confirmed path parsing — resource basenames/directories containing periods are truncated.** `resource/CustomResourceTools.java:20` selects `split("\\.")[0]` before adding the desired extension, even though resource paths may contain earlier periods. Strip only the final extension from the filename while preserving namespaces and directories, with explicit round-trip cases.
3. **P2, shared-holder follow-up — door mapping still appends across successful variants.** `model/BuiltVehicleModelHolder.java:75-89` unconditionally adds mapped door details. Moving the call after bogie readiness removes retry amplification, but a cached holder reused by distinct successful legacy consist-cache variants can still accumulate mappings. A one-time guard is not safe without checking whether each variant has different doorway geometry; cache ownership must be resolved first.
4. **P2, static mismatch requiring game verification — custom rail light uses raw brightness.** `render/RenderRails.java:274` forwards `getMaxLocalRawBrightness()` directly through `RailResource`/`StoredModelResourceBase.render` into the packed-light render API, while the default rail path at line 299 explicitly uses `LightTexture.pack(block, sky)`. Values 0-15 are not normal packed block/sky light coordinates. Verify custom rail lighting under both renderer backends and use the established packed-light convention if confirmed.
5. **P2 performance — rail editor scans a 33-cubed neighborhood per rendered frame.** `render/RenderRails.java:218-227` checks 35,937 world positions whenever a rail-related item is held, in addition to rendering known nodes. Candidate caching keyed to player chunk/position and block updates could avoid this repeated client-world traversal. This is an existing cost observed in source, not a measured benchmark.
6. **P2 lifecycle — lift path cache retains the last world after disconnect.** `render/RenderLifts.java:334-358` stores a static strong `ClientLevel` reference. It changes only on the next lift-path lookup or world mismatch, so its nominal two-second TTL is not a disconnect cleanup. Add explicit lifecycle clearing or weak-world ownership when revisiting this subsystem. `LIFT_MODEL_CACHE` is bounded to 256 entries and does not itself retain the world.
7. **P2 correctness follow-up — sign caches omit world identity.** `resource/SignResource.java:54-59,217-308` uses static position/ID-only caches for stations/platforms/routes, with a five-second approximate timeout and no local explicit reset method. Reusing the same coordinates or IDs immediately after changing worlds can reuse prior-world data. A world/session component or reset hook should be added with lifecycle tests; no live transition was tested.
8. **P3 hierarchy compatibility — parent outline transformations deserve dedicated fixtures.** `model/BlockbenchModelLoader.java:100-104` recurses with the prior `groupTransformations` rather than the computed new chain; `BlockbenchOutline.add` also treats a root specially. The bounds fix deliberately follows the actual rendering chain, and does not reinterpret legacy model hierarchy. Compare nested Blockbench fixture geometry before changing that behavior.
9. **P3 resource robustness — display zero padding is unbounded.** `resource/ModelPropertiesPart.java:421` repeatedly prepends zeros up to the externally supplied double-valued `displayPadZeros`. Malformed values can cause excessive allocation/work; reject nonfinite and cap practical display lengths at resource validation, preserving normal packs.
10. **P3 render costs — repeated scans and geometry preparation remain.** `RenderStationNameTiled.getLength` walks the connected row from every block each frame (quadratic total row work); the existing `RouteMapSpanCache` optimization currently targets APG/PSD. `RenderLiftPanel` scans all lifts for each panel. `DrivingGuiRenderer` recreates background/tick geometry each frame. These are candidates for measured cache/batching work, with invalidation and display behavior retained.
11. **P3 exceptional-path state — some helper PoseStack pushes lack finally-pop.** `BlockEntityRendererExtension.render` and several small callback helpers push, call rendering, then pop without `finally`. A thrown resource/font exception can leave the shared pose stack unbalanced if the caller continues. The PIDS separator crash is fixed, but exceptional cleanup should be made consistent in a separate bounded change.
12. **P3 precision/contract observations.** `RenderClock` multiplies total world day time into float rotations without first reducing to the clock period, losing precision in sufficiently old worlds. `MinecraftModelResource` overrides `equals` without `hashCode`; the current reviewed `ObjectArraySet` consumers do not need hash lookup, but future hashed collections would violate the contract. `RenderEyeCandy.shouldRender` always returns true; safe culling requires model-aware bounds because decorative models may extend arbitrarily beyond their block.

No new change was made for these unresolved findings. Their presence means the completed static pass is not a claim that every subsystem is defect-free or runtime-verified.
